# cost-and-budget

## Purpose

Netzが本人専用・追加費用ゼロでテーマ調査を実行するための、cost-and-budgetに関する観測可能な契約を定義する。既存Issueの実装予定を表し、現時点で実装・実機検証が済んだことを意味しない。

## ADDED Requirements

### Requirement: 追加費用ゼロでの停止

システムは無料プラン・枠内だけで動作しなければならない（MUST）。無料枠を使い切ったらquota_exhaustedとして止まり、有料契約・超過課金・未承認フォールバックで継続してはならない（MUST NOT）。

#### Scenario: 枠切れ

- **WHEN** プロバイダの日次・月次無料枠が不足する
- **THEN** 即時再試行を繰り返さず停止し、有料経路へ切り替えない

#### Scenario: 料金条件が不明

- **WHEN** アカウントの課金設定や無料停止条件が確認できない
- **THEN** 無料運用が確認できるまでそのサービスを採用しない

### Requirement: 依頼全体での処理予算

初期上限は検索3回、本文取得5ページ、推論4回としなければならない（MUST）。計画・修正・整理・再試行を合算し、MCP・直接経路・再開・同時実行を横断して送信前に予算を確保しなければならない（MUST）。

#### Scenario: 経路変更と同時実行

- **WHEN** 複数MCPと直接経路へ並行検索する
- **THEN** 合計で3回を超える送信を拒否し、4回目は実行されない

#### Scenario: 再配信と結果不明

- **WHEN** 使用済みの依頼を再開する、または送信後に応答が失われる
- **THEN** 使用済み予算を初期化・返還せず、証跡と対応づけて扱う

### Requirement: 状態の永続化と限定的な再試行

システムは計画、承認、証拠、予算、判定、保存状態を再開可能に保持しなければならない（MUST）。一時障害だけを上限付きで再試行し、確認待ちをQueueの再配送ループで実現してはならない（MUST NOT）。

#### Scenario: 確認待ちの再開

- **WHEN** プロセスが停止した後に本人が現在の計画を承認する
- **THEN** 同じrequestId・planVersion・予算で一度だけ再開する

#### Scenario: 期限切れ

- **WHEN** 確認待ちの保持期限を超えて承認する
- **THEN** expiredとして拒否し、計画を黙って再生成しない
